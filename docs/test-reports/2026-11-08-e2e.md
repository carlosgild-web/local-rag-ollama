# End-to-end test, 2026-11-08 (v0.5.0, UI improvements)

**What was tested:** the whole app on the `feature/ui-improvements` branch, starting from an empty database, with:
- a real Ollama: `qwen2.5:3b` for chat, `bge-m3` for embeddings
- the 11 sample documents in `e2e/corpus/` (fictional Hilda & Luna Beadworks data)
- edited versions, new documents and edge cases
- the endpoints added on the branch (new phase `ui_endpoints`), and restore from trash

**How:** `e2e/run_e2e.py` with `e2e/scenario.json`, on an isolated server (port 8001, its own data folder). The restart check killed and restarted that server. The web UI was checked separately in Chrome for the screenshots in `docs/showcase/`.

**Detailed results:** [run report](2026-11-08-e2e-run-report.md), with every question, answer, source and timing.

**Machine:** Ryzen 5 7520U laptop, 7.2 GB RAM, CPU only. The median answer took 43.9 s, the slowest 122 s.

## Verdict

**All 53 must-pass checks passed.** The app mechanics are unchanged from run 2, and everything added on the branch works:

| New check | Result |
|---|---|
| Upload rules list the readable types and the size limit | ✅ |
| Review before upload: a stored file is "duplicate", a new one "new" | ✅ |
| Troubleshooter checks report no failure on a healthy system | ✅ |
| Suggested shelves: re-dropping the corpus marks all 11 files "already in the library" | ✅ |
| Suggested shelves: the analysis indexes nothing before confirmation (11 → 11 documents) | ✅ |
| Cancelling an analysis removes the staged files | ✅ |
| A trashed document can be restored | ✅ |
| A new travel expense policy is suggested for the `hr` shelf (quality check) | ✅ marked "please check": it also fits `sales-customers` |

The existing checks passed too:
- **Ingestion:** PDF, Word including tables, text and Markdown.
- **Versions and rollback.**
- **Trash:** a trashed document is never cited.
- **Duplicates and bad files.**
- **Jobs:** cancel and retry.
- **Reindex and blue/green rebuild.**
- **Crash recovery:** the job interrupted by the restart completed, and documents, trash and 55 chat sessions survived.

**Grounding holds:** 7 of 7 off-topic, wrong-shelf and missing-fact questions were answered "not found in the documents". The prompt-injection document did not take over any answer.

## The 5 quality failures

All five are *answer misses*: the right passage was retrieved, but the 3B model didn't state the fact as expected.

| Check | What happened | Also failed in run 2? |
|---|---|---|
| hr-02, holiday party time and place | Gave the date and place, left out the time (6:00 PM). | yes |
| hr-04, gloves for resin | Right answer ("nitrile"), but cited as `[N1][N2]` instead of `[1]`, so the citation check marks it uncited. | no (passed) |
| sc-06, are antique bronze charms nickel-free | "Not found in the documents", though the FAQ passage was retrieved. | yes |
| sc-07, wholesale account approval time | Same: the FAQ passage was retrieved, the model said "not found". | yes |
| inj-01, which foundry casts pewter charms | Answered only `[1]`, with no text. The document holding the fact also holds the injection attempt. | yes |

sc-06 and sc-07 are the open finding 5 from 2026-11-06: both depend on `08-customer-faq.txt`. That is the next thing to look at, in the Phase 7 evaluation, together with a larger model on better hardware (decision 0004).
