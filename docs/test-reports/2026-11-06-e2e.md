# End-to-end test, 2026-11-06

**What was tested:** the whole app, starting from an empty database, with:
- a real Ollama: `qwen2.5:3b` for chat, `bge-m3` for embeddings
- the 11 sample documents in `e2e/corpus/` (fictional Hilda & Luna Beadworks data)
- edited versions, new documents and edge cases
- the web UI, driven in Chrome

**How:** `e2e/run_e2e.py` with `e2e/scenario.json`. An independent reviewer agent then re-graded every answer against the document text.

**Detailed files:**
- [run report](2026-11-06-e2e-run-report.md): every question, answer, source and timing
- [independent review](2026-11-06-e2e-independent-review.md)

**Machine:** Ryzen 5 7520U laptop, 7.2 GB RAM, CPU only. The median answer took 41.5 s, the slowest 113 s.

## Verdict

**The app mechanics work.** All 54 API checks passed:
- **Ingestion:** PDF, Word including tables, text and Markdown.
- **Versions:** a changed file became v2 of the same document, and the old answers kept their original sources.
- **Rollback:** instant, with no re-embedding.
- **Trash:** a trashed document was never cited again.
- **Duplicates and bad files:** duplicates were skipped, and unsupported files were refused with a 415.
- **Jobs:** cancel and retry worked.
- **Reindexing:** both in place and as a blue/green rebuild.
- **Crash recovery:** a job interrupted by killing the server was recovered on restart. Documents, trash and chat history survived.
- **Audit log** and **feedback** were recorded.

**Grounding is solid:**
- **Off-topic questions:** 7 of 7 refused with "not found in the documents", including questions asked on the wrong shelf and questions about missing facts.
- **Prompt injection:** ignored. No answer contained "BANANA".
- **Shelves:** no answer used a document from another shelf, a trashed document or a superseded version.

**The weak spots are citations and three UI bugs.**

| Area | Result |
|---|---|
| Answer content (reviewer) | 43 correct, 2 partly correct, 0 wrong, 9 correct "not found", 2 wrongly "not found" (56 answers) |
| Citations (reviewer, 45 answers that should cite) | 29 correct (64%), 5 cite the wrong document, 2 cite a number that doesn't exist, 9 missing |
| Hallucination | 1: hr-12 turned "first 6 weeks paid" into "primer semestre" (first half-year) |
| UI (Chrome) | 10 of 14 checks passed; 3 bugs, 1 quality issue |

## Findings and proposed fixes

Ordered by impact. Nothing has been fixed yet; app code stays unchanged until you approve.

| # | Finding | Kind | Proposed fix |
|---|---|---|---|
| 1 | **Citations are unreliable.** 36% are missing or wrong, sometimes pointing at a document that says the opposite (hr-13 cites the handbook's "February" for a December 18 answer). Invariant 6 makes citations mandatory. | model quality | Tighten the prompt and add a short example of a cited answer. Check citations on the server: if an answer has none, or an out-of-range number, keep the answer but flag it as "unverified" in the UI, and always show the source list. Measure in Phase 7 (evaluation). |
| 2 | **Cancel doesn't stop a pending job** (UI). The job's status is overwritten by the worker. The cancel request also waited 9 s for the database lock. | bug, race | Make each job state change conditional: run a job only if it is still pending, and cancel it only if it is still pending. Otherwise ask the running job to stop. Add a regression test. |
| 3 | **The Chat shelf picker resets after a refresh,** and asking without a shelf silently creates an empty "default" shelf that answers "not found". | bug, UX | Remember the shelf per chat session, and pick the only or last-used shelf instead of an empty default. Never create the default shelf from a chat. |
| 4 | **A stopped answer disappears** until the page is refreshed. The server does save it. | bug, UX | Keep the partial answer on screen after Stop, then refetch once the server has saved it. |
| 5 | **Wrongly "not found" twice.** sc-06 (nickel): the passage was retrieved, but the 3B model was too cautious. new-04: an English question about a Spanish document didn't retrieve it. | model / retrieval | A larger chat model on better hardware; review in Phase 7. Possibly increase the number of passages retrieved (top-k) for cross-language questions. |
| 6 | **The "Change" form lists chat models as embedding models,** and `bge-m3` twice. | UX bug | Only offer models whose Ollama details mark them as embedding models, and show each name once. |
| 7 | **An empty file is accepted** as a document with 0 chunks. | validation | Refuse empty files, or files with no text, with a clear message. |
| 8 | **A 2-page PDF becomes one passage labelled "page 1",** so citations can name the wrong page. | ingestion | Don't merge text across pages when chunking a PDF. |
| 9 | **A follow-up question** ("And what is its wholesale price?") **was answered about a different product.** | known limitation | Planned: pass the earlier turns of the conversation to the model (later phase). Until then, the UI already says each question is answered on its own. |
| 10 | **A retired shelf copy still answers** if asked by its id. | minor | Refuse questions on inactive collections. |
| 11 | **Minor UX:** the "Queued 1 file…" message stays on screen after indexing; reindex jobs show "document 1" instead of the file name; a file already on another shelf is skipped without a message. | UX | Fold into the UI changes. |

## Test-tool notes

- **Unit tests:** the 101 backend tests stay green, since no app code was changed during the test.
- **Process stops:** the run was stopped twice, once by Claude Code's low-memory protection and once deliberately. It resumed with `--resume`. Some HR questions were asked twice, and the report keeps the latest answers.
- **Automatic citation check:** it only failed missing citations. Wrong and out-of-range numbers are now counted separately in the run report, and the reviewer graded them all.
- **Cause labels:** the automatic "answer miss" label for new-04 should read "retrieval miss". The reviewer's labels are the reliable ones.
- **No UI screenshots:** Chrome screenshots timed out while memory was full, so the UI checks were done by reading the page and clicking elements.
